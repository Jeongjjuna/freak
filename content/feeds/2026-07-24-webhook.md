## Webhook — "사건 터지면 내 HTTP API로 쏴라"

Webhook은 **특정 이벤트가 발생했을 때, 상대방이 내가 열어둔 HTTP API를 호출해 주는 이벤트 기반 콜백**입니다.

### 포인트1 — 내 서버에 엔드포인트를 열어둔다 (Reverse API)

```java
@PostMapping("/api/v1/webhooks/payment")
public ResponseEntity<Void> handlePaymentEvent(@RequestBody PaymentPayload payload) {
    // PG사가 "입금 완료" 이벤트를 내 엔드포인트로 쏴주면 비즈니스 로직 수행
    paymentService.completeOrder(payload.getOrderId());
    return ResponseEntity.ok().build();
}
```

"처리 끝났어?" 하고 주기적으로 찌르는 **Polling 방식이 아닙니다.**

내가 남의 API를 부르는 게 아니라 상대방이 내 서버의 API를 호출해주기 때문에 '**역방향 API(Reverse API)**'라고 부릅니다.

### 포인트2 — 무조건 HTTP 기반의 API다

```text
[이벤트 발생 주체] ──── HTTP POST /webhook ────▶ [이벤트 수신 서버]
(GitHub 코드 Push,                             (Slack 메시지 전송,
PG사 무통장 입금 완료)                          DB 주문 상태 변경)
```

이벤트를 전달하는 기술(Kafka, WebSocket 등)은 많지만, **HTTP/HTTPS 프로토콜을 사용해 상대방의 REST API를 호출할 때만 Webhook**이라 부릅니다.

슬랙 알림 전송, 결제 완료 통보, GitHub CI/CD 연동이 모두 이 HTTP API 규격을 따릅니다.

이벤트를 일으킨 주체가 **'HTTP POST' 갈고리를 걸어 내 API로 데이터를 꽂아주는 것**입니다.

<br>

> `핵심` — Webhook은 "사건이 터졌을 때 상대방이 내 서버의 HTTP API를 호출하는 Push 방식의 알림"이다.
