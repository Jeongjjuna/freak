## APM — 메트릭으로 이상을 찾고, 요청을 따라가며 원인을 찾는다

APM(Application Performance Monitoring)은 **애플리케이션의 요청 흐름을 추적해 성능 문제의 원인을 찾는 도구**입니다.

메트릭이 애플리케이션의 상태를 **숫자로 확인**하는 데 초점을 둔다면, APM은 **하나의 요청을 따라가며 어디에서 문제가 발생했는지 확인**하는 데 초점을 둡니다.

### 포인트1 — 메트릭은 "이상하다"를 알려준다

예를 들어 메트릭을 확인했더니 API 응답 시간이 증가했다고 해보겠습니다.

```text
/api/coupons

평균 응답 시간
100ms → 2,000ms
```

하지만 이것만으로는 왜 느려졌는지 알기 어렵습니다.

DB가 느린가?
외부 API가 느린가?
애플리케이션 코드가 느린가?

메트릭은 주로 현재 시스템에 무슨 일이 일어나고 있는지 보여줍니다.

### 포인트2 — APM은 "어디가 문제인지" 보여준다

APM에서는 실제 요청 하나를 따라가 볼 수 있습니다.

```text
GET /api/coupons     2,000ms
│
├── Controller       10ms
├── Service          20ms
├── DB Query       1,800ms  ← 문제
└── Response        170ms
```
전체 요청이 2초 걸렸지만, 실제로는 DB Query에서 대부분의 시간이 사용되고 있다는 것을 확인할 수 있습니다.

즉, 메트릭 → API가 느려졌다.

APM → DB Query가 느리다.

라는 차이가 있습니다.

### 포인트3 — 그래서 같이 사용한다

둘은 서로 대체하는 관계가 아닙니다.

```text
[Metric]

API 응답 시간 ↑
│
▼
"문제가 있네?"
│
▼
[APM]

요청 추적
↓
DB Query 1.8s
↓
"여기가 문제구나."
```

메트릭으로 이상을 발견하고, APM으로 원인을 찾는 것입니다.

<br>

> `핵심` — 메트릭이 "무슨 문제가 발생했는지" 숫자로 보여준다면, APM은 "그 문제가 어디에서 발생했는지" 요청을 따라가며 보여준다.
